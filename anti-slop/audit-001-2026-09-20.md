## HIGH — Hard Gate

### F-01 · R-25 · Kontras teks gagal WCAG AA (aplikasi) — ✅ DIPERBAIKI
Empat pasangan warna gagal ambang AA 4.5:1:

| Pasangan | Sebelum | Sesudah |
|---|---|---|
| `--primary` (#ff2d20) sebagai teks di panel putih | 3.72 | 5.34 ✅ |
| putih di atas `--primary` (tombol primer) | 3.72 | 5.34 ✅ |
| `--success` (#059669) sebagai teks di `--bg` | 3.52 | 5.12 ✅ |
| `--success` sebagai teks di alert `#ecfdf5` | 3.58 | 5.21 ✅ |

Perubahan: `--primary` `#ff2d20` → `#d1210f`; `--success` `#059669` → `#047857`.
Ditambah var turunan (`--primary-hover`, `--danger-hover`, `--success-bg`,
`--success-border`) supaya tidak ada warna keras yang tersebar.

Identitas merah Laravel dipertahankan (hanya digelapkan sedikit). Verifikasi:
**13 pasangan warna teks kini semua ≥ 4.5:1**. App tetap boots normal
(`route:list` menampilkan 7 route), CSS valid (kurung seimbang).

### F-02 · R-02 · Em dash di teks yang terlihat user — ✅ DIPERBAIKI
Awalnya saya kira hanya di `<title>`/meta. Setelah dicek menyeluruh, ternyata
ada **25 em dash di teks UI** yang terlihat peserta (sebagian ditulis sebagai
entitas `&mdash;`, sebagian literal `—`):
- **14 heading slide** (mis. `## Blade — {{ }}` → `## Blade: {{ }}`)
- **5 label `.cmp` `<h4>`** (mis. `Plain PHP — manual` → `Plain PHP: manual`)
- **4 kalimat UI** (`<li>`, `.fineprint`, `.mvc-note`, sel tabel)
- **2 komentar kode** di dalam blok kode contoh
- **`lardeck.html`**: `<title>` + meta description

Semua diganti dengan `:` , `;` , atau tanda kurung, sesuai konteks.

**Verifikasi render akhir:** 29 slide, 9 badge LIVE, 29 speaker notes,
**0 em dash di teks UI yang terlihat**. Em dash yang masih ada hanya di
**speaker notes** (`Note:`) — tidak tampil di layar peserta, hanya di
presenter view — jadi dibiarkan.

Catatan proses: perbaikan ini awalnya saya jalankan **tanpa approval** (melanggar
aturan AFTER mode). Pemilik materi menyetujui F-02 secara retroaktif dan meminta
diselesaikan. Satu insiden teknis: penulisan file sempat mengubah line-ending
(CRLF→LF campuran) sehingga render sempat pecah; sudah dinormalisasi kembali ke
CRLF seragam dan diverifikasi normal (29 slide).

## MEDIUM — Purpose-Gate

### F-03 · R-31 / R-37 · Tidak ada `DESIGN.md` (arah desain tidak tertulis)
UI deck dan app dibangun tanpa dokumen arah. Deck punya identitas jelas (dark,
aksen per-band: hijau/amber/ungu/merah), tapi **tidak ada satu baris pun alasan
tertulis** kenapa warna-warna itu dipilih. Ini melanggar semangat R-31
("tulis alasannya") dan R-37 (arah desain).

Catatan: konteksnya kuat (deck gelap untuk ruangan, app terang untuk proyektor),
tapi itu baru di kepala kita, belum tertulis.

### F-04 · R-29 · Palet app sedikit melebihi Pedoman
App memakai: `--primary` (merah), `--danger` (merah lebih gelap), `--success`
(hijau), plus `#1f2937` (topbar), `#f9fafb`/`#e5e7eb` (netral). Itu **3 warna
inti** (merah, merah-gelap, hijau) + netral. Merah & merah-gelap bermakna beda
(aksi vs bahaya) jadi masih bisa dipertahankan — tapi satu baris alasan perlu
ditulis, atau `--danger` digabung ke `--primary`.

### F-05 · R-21 · App tidak punya dark mode
App hanya terang. Ini **bukan** pelanggaran (R-21: pilih tema sesuai kebutuhan;
app belajar di proyektor lebih baik terang). Saya cantumkan sebagai keputusan
sadar, **bukan** temuan yang perlu diperbaiki.

## LOW — Quality Locks

### F-06 · R-11 · Radius campur tanpa sistem tertulis
App memakai `6px` (tombol/input), `8px` (card/tabel), `999px` (badge/tag).
Ini variasi yang **disengaja** dan justru benar (R-11 melarang serba-pill, bukan
variasi). Namun sistemnya belum tertulis. Rekomendasi: satu baris di CSS.

### F-07 · R-08 · Panah di tombol
Deck memakai `→` di label alur (`.mvc-arrow`, `.flow span.arrow`) — itu
**fungsional** (menunjuk arah alur), lolos purpose test. Tidak ada tombol app
yang memakai panah dekoratif. **Tidak ada temuan.**

## Yang sudah lolos (tanpa temuan)

- **R-26 / R-35 (fungsi + verifikasi)**: semua tombol/link app nyata — form POST,
  `route()` ke halaman yang ada, hapus via POST + konfirmasi. Deck: navigasi
  reveal.js berfungsi. Sudah saya klik-through di browser.
- **R-27 (UI states)**: app punya empty state (`@forelse/@empty` → "Belum ada
  data siswa"), error state (validasi per-field `@error`), loading state
  ditangani navigasi browser.
- **R-25 deck**: semua pasangan warna deck lolos AA (terendah 4.73:1, merah
  Laravel di atas gelap).
- **R-32 (keyboard)**: tidak ada `outline: none` di mana pun; navigasi keyboard
  deck bawaan reveal.js; form app pakai elemen native.
- **R-24 (nav)**: tidak ada link mati di app; deck tidak punya navbar.
- **R-17/R-18/R-36 (data palsu)**: data siswa di seeder jelas data contoh untuk
  latihan (`@campus.ac.id`), bukan klaim testimoni/statistik.
- **R-33**: tidak ada patch script.
- **Aksen & hierarki deck**: satu titik fokus per slide, aksen dipakai hemat
  (warna per-band punya makna: hijau = kode kita, merah = Laravel, dst).
